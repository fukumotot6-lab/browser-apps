# 設計

マインスイーパーのファイル構成と、層の分け方、そうした理由を書きます。段階が進むごとに更新します。全アプリ共通の決まりは [規約](../../../docs/conventions.md) にあります。

## ファイル構成

```
apps/minesweeper/
  index.html            ページの入口。機雷、旗、顔の絵（SVG）の定義もここにある
  vite.config.ts        ビルドと単体テストの設定
  playwright.config.ts  ブラウザテストの設定
  src/
    main.ts             画面を組み立てる入口
    logic/              ロジック層
      types.ts              型の定義
      mine-placement.ts     機雷の配置
      game.ts               ゲームの作成、マスを開く、旗、勝敗判定
      cell-view.ts          マスの見せ方への変換
      index.ts              描画層に公開するものの一覧
    ui/                 描画層
      difficulty.ts         難易度3種類の定義
      display.ts            3桁表示の変換、7セグメントの点灯表、顔と通知の文言
      timer.ts              経過秒の計算
      mouse-input.ts        マウスのボタン操作を「開く」「旗」「周囲を開く」に変換
      app.ts                部品をつなぎ、ゲームの状態とタイマーを持つ
      board-view.ts         盤面
      status-bar.ts         残り機雷数、顔のボタン、タイマーの帯
      difficulty-bar.ts     難易度ボタン
      seven-segment.ts      7セグメント風の表示器
      svg.ts                SVGの要素を作る補助
      style.css             見た目
  tests/
    logic/              ロジック層の単体テスト（Vitest）
    ui/                 描画層のうち、DOMに触れない関数の単体テスト（Vitest）
    browser/            実際のブラウザを操作するテスト（Playwright）
  docs/                 このアプリの要件定義書、設計、段階レポート
```

`ui/` の上の4つ（`difficulty.ts` から `mouse-input.ts` まで）はDOMに触れません。残りがDOMに触れます。

## 層の分け方

| 層         | 場所         | 役割                                                     | 触れてはいけないもの            |
| ---------- | ------------ | -------------------------------------------------------- | ------------------------------- |
| ロジック層 | `src/logic/` | 盤面の状態と操作（開く、旗、勝敗判定）                   | DOM、`window`、タイマー、描画層 |
| 描画層     | `src/ui/`    | 状態を画面に反映し、クリックをロジック層の操作に変換する | ゲームのルール                  |

依存の向きは、描画層からロジック層への一方向です。描画層は `logic/index.ts` が公開するものだけを使います。

## そうした理由

- **ロジックをNode.js上でテストするため**。ブラウザを起動せずに、機雷の配置や勝敗判定を速く、確実に確かめられます。テストはブラウザ環境を模擬しない設定（`vite.config.ts` の `environment: 'node'`）で動かすので、ロジック層がDOMに触れるとテストが失敗します
- **将来の拡張で描画層だけ、またはロジック層だけを差し替えられるようにするため**。たとえばスマホ対応は描画層だけの変更で済みます
- **盤面サイズと機雷数を引数で受け取るため**。難易度3種類はロジック層に埋め込まず、呼び出す側が持ちます。カスタム盤面を足すときにロジック層を変えずに済みます

## ロジック層の作り

### 状態と操作

ゲームの状態は `GameState` という1つの値で表します。操作は、状態を受け取って新しい状態を返す関数です。

| 関数                                    | 役割                                       |
| --------------------------------------- | ------------------------------------------ |
| `createGame(config)`                    | 新しいゲームを作る                         |
| `openCell(state, position, placeMines)` | マスを開く                                 |
| `openNeighbours(state, position)`       | 開いている数字のマスの周囲を、まとめて開く |
| `toggleFlag(state, position)`           | 旗を立てる・外す                           |
| `countRemainingMines(state)`            | 残り機雷数（機雷数 − 旗の数）を求める      |
| `getCellView(state, position)`          | 1つのマスを画面にどう見せるかを求める      |
| `createRandomMinePlacer(random)`        | 乱数から、機雷を配置する関数を作る         |

- **渡された状態を書き換えません**。操作のたびに新しい状態を返します。前後の状態を比べられるので、テストが書きやすくなります
- **何も変わらない操作では、渡された状態をそのまま返します**。描画層は、返ってきた状態が同じものかどうかを見るだけで、描き直しを省けます
- **マスは1次元の配列で持ちます**。位置 `{ x, y }` のマスは `y × 幅 + x` 番目です。外から位置を受け取る関数は、盤面の外や整数でない位置をエラーにします

### 進行状況

```
ready ──最初のマスを開く──▶ playing ──機雷のないマスをすべて開く──▶ won
                              │
                              └──機雷を開く──▶ lost
```

- `ready` のあいだは機雷を置きません。最初に開くマスが決まってから配置することで、そのマスに機雷がないことを保証します
- 最初の1手で機雷のないマスがすべて開いた場合は、`ready` から直接 `won` になります
- タイマーはロジック層にありません。描画層が、`ready` からの変化を見て動かします

### 機雷の配置を外から渡す

`openCell` は、機雷を配置する関数（`MinePlacer`）を引数で受け取ります。

- 本番では、`Math.random` を使う配置関数を `createRandomMinePlacer` で作って渡します
- テストでは、決まった位置を返す関数を渡して、盤面を固定します
- 将来「推測なしモード」を足すときは、別の配置関数を渡すだけで済みます

渡された関数の結果は、そのまま信用せずに検証します（個数、重複、範囲、最初のマスを含まないこと）。

### 見せ方の変換

負けたときに何を明かすかはゲームのルールなので、ロジック層の `getCellView` が決めます。描画層は、返ってきた種類に応じた絵を描くだけです。

| 種類            | 意味                                             |
| --------------- | ------------------------------------------------ |
| `hidden`        | 閉じたマス                                       |
| `flag`          | 旗                                               |
| `open`          | 開いたマス。周囲の機雷の数を持つ                 |
| `mine`          | 負けたときに明かされる、旗の立っていない機雷     |
| `exploded-mine` | 負けの原因になった機雷                           |
| `wrong-flag`    | 負けたときに明かされる、機雷のないマスに立てた旗 |

## 描画層の作り

### 全体の流れ

`app.ts` が、現在の `GameState` を1つ持ちます。操作のたびにロジック層の関数を呼び、返ってきた状態が前と別のものなら、画面を描き直します。

```
マウスの操作 ─▶ mouse-input.ts（どの操作かを決める）
             ─▶ app.ts（ロジック層の関数を呼ぶ）
             ─▶ 新しい GameState
             ─▶ board-view.ts / status-bar.ts（画面に反映）
```

盤面は、マスごとに `getCellView` の結果を見て描きます。前に描いた見せ方と同じマスは書き換えません。

### マウスの操作

| 操作                           | 動作                                 | 呼ぶ関数         |
| ------------------------------ | ------------------------------------ | ---------------- |
| 左ボタンを離す                 | ポインタの下のマスを開く             | `openCell`       |
| 右ボタンを押す                 | 旗を立てる・外す                     | `toggleFlag`     |
| 左右を押して、どちらかを離す   | 開いた数字のマスの周囲をまとめて開く | `openNeighbours` |
| 中ボタンを離す                 | 同上                                 | `openNeighbours` |
| 両押しのあと、残った片方を離す | 何もしない                           | —                |

ボタンの押下と解放の列をどの操作と見なすかは、`mouse-input.ts` の状態機械が決めます。DOMに触れない関数（`stepMouse`）なので、単体テストで列を1つずつ確かめています。ウィンドウの外でボタンを離された場合に状態が残らないよう、毎回 `MouseEvent.buttons`（いま押されているボタン）と突き合わせます。

### タイマー

- 状態が `ready` から変わった時（最初のマスを開いた時）に始め、勝ち・負けで止めます
- 表示する秒は、開始時刻と現在時刻の差から求めます。割り込みの回数は数えません。タブが裏に回って割り込みが間引かれても、正しい値に戻れます
- 999で止めます

### 絵と見た目

- 機雷、旗、誤った旗、顔3種類は、`index.html` に `<symbol>` として定義した自作のSVGです。JavaScriptからは `<use href="#icon-…">` で参照します。絵を文字列として組み立てないので、`innerHTML` を使いません
- 残り機雷数とタイマーは、SVGで描いた7セグメント風の表示器です
- 外部の画像、フォント、スクリプトは読み込みません。HTMLにインラインのスクリプトとstyle属性を書いていません（段階3でCSPを入れるための準備）
- 勝敗は顔のボタンの表情で示します。絵が見えない利用者のために、画面には出さない通知領域にも文言を入れます

### テストから見える目印

ブラウザテストがマスやボタンを見つけられるよう、要素に次の属性を付けています。

| 要素         | 目印                                                                   |
| ------------ | ---------------------------------------------------------------------- |
| 難易度ボタン | `data-difficulty`、選択中は `aria-pressed="true"`                      |
| 残り機雷数   | `data-testid="mine-counter"`、表示中の3文字が `data-value`             |
| タイマー     | `data-testid="timer"`、表示中の3文字が `data-value`                    |
| 顔のボタン   | `data-testid="reset-button"`、表情が `data-face`                       |
| 盤面         | `data-testid="board"`、`data-width`、`data-height`                     |
| マス         | `data-x`、`data-y`、見せ方の種類が `data-kind`、数字が `data-adjacent` |
| 通知領域     | `data-testid="status-message"`                                         |

## テストの分け方

| 種類           | 道具       | 場所             | 確かめること                                          |
| -------------- | ---------- | ---------------- | ----------------------------------------------------- |
| 単体テスト     | Vitest     | `tests/logic/`   | ゲームのルール                                        |
| 単体テスト     | Vitest     | `tests/ui/`      | 描画層のうち、DOMに触れない関数                       |
| ブラウザテスト | Playwright | `tests/browser/` | ビルドした成果物を、実際のブラウザ3種類で操作した結果 |

ブラウザテストでは、機雷の位置を次の方法で固定します。本番のコードにテスト用の入口はありません。

1. ページを読み込む前に、`Math.random` を種つきの乱数に差し替える
2. テストの側でも同じ種の乱数でロジック層の配置関数を呼び、機雷の位置を求める

この方法が成り立つよう、描画層は機雷の配置以外の目的で `Math.random` を呼びません。タイマーは、Playwrightの時計を進める機能で確かめます。

## 仕組みで守っていること

- ロジック層でブラウザのAPIやタイマーを使うと、ESLintがエラーにします（ルートの `eslint.config.js`）
- ロジック層から描画層を読み込むと、ESLintがエラーにします
- 成果物の参照は相対パスにしています（`vite.config.ts` の `base: './'`）。公開先のURLがサブパスになっても、設定を変えずに動きます
